# 60-second demo

Before recording: `.env` filled, `python scripts/check_connections.py` green,
`python scripts/seed_memory.py` seeded, `streamlit run app.py` open, browser
zoomed to ~110%. Keep the **Live incident** tab selected. Data is simulated.

---

**0:00 — The 3am problem.**
> "It's 3am. Checkout is down, and the on-call engineer has never seen this exact
> failure. Generic runbooks say restart the service. Last time, that made it worse."

**0:06 — A fresh alert.**
Click **Trigger next incident** until a TLS or memory-leak incident is selected
(`INC-103` for TLS is ideal — use the dropdown for a deterministic recording).
> "A P1 on payments-service: TLS handshake failures. The agent reads the logs,
> checks recent deploys, and pulls the metrics."

Point at the live trace: logs → deploys → metrics → recall → reasoning.

**0:16 — Memory OFF.**
Turn **Memory ON** off in the right panel. The result card reruns.
> "With memory off, it has the logs but no history. It falls back to the generic
> restart-and-rollback answer. Restart is ranked first — and on this failure it
> will not work."

**0:26 — Memory ON.**
Turn **Memory ON** back on, then click **Run memory OFF vs ON comparison**.
> "Same alert, same model, same logs — only recall differs. Memory finds the
> expired certificate in four past incidents. Renewing the certificate moved from
> nowhere to the first fix, with the exact count: worked 4/4. Restart is demoted
> because memory records it failing every time."

**0:40 — The engineer resolves it.**
In the main result card, add the note "cert renewed, handshakes recovered" and
click **Worked** under `renew_certificate`.
> "One click stores the outcome in Hindsight. Next time this pattern appears —
> on any service — the agent already knows."

**0:48 — What the benchmark can and cannot show.**
Open the **Learning curve** tab.
> "The full benchmark didn't finish — I hit the free Groq quota on one attempt and
> lost Hindsight connectivity on another — so I'm not quoting numbers from it. The
> memory evidence is the comparison I just ran: same alert, memory off ranks a
> restart first, memory on recalls the certificate fixes and puts them on top.
> This is memory, not model retraining."

**0:56 — Close.**
> "OnCall Memory: the team's incident history, available at 3am. Simulated data,
> advisory only, nothing is executed."

---

## Reset between takes

- The demo bank keeps every outcome you click. Re-seed a clean bank:
  `python scripts/seed_memory.py --reset --force`
- If you want a clean event feed, restart the app (session state resets).
- The benchmark CSV/chart is only regenerated by `python -m oncall.evaluate`.

## If the network fails on stage

The app never crashes: a banner says Hindsight is unavailable and shows the
clearly-labelled local keyword fallback; the deterministic analyst answers if
Groq fails. Say so plainly rather than hiding it — the reliability ladder is part
of the engineering.
